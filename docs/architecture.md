# 設計方針

状態: 一粒子等速直線運動（$x = x_0 + v t$）および調和振動子の実装まで反映。v0.1のMD仕様と後続段階は設計方針であり、実装済み機能と区別する。

## 責務と依存方向

計算はRustで行い、Wasm-firstでNativeも同時に対応する。Coreは原子、力場、金融商品、電子密度、画面、ファイルシステムを知らない。

```text
Studio → Worker → Wasm境界 → Dynamics → Core
CLI                       → Dynamics → Core
将来の実行入口            → Quant / Electronic → Core
```

| 層 | 所有する責務 | 持ち込まない責務 |
| --- | --- | --- |
| Core | 数値状態、時間積分、共通化が実証された数値演算 | 分野固有モデル、ブラウザ・OS操作 |
| Dynamics | 粒子、境界条件、力場、物理量 | DOM、ファイル保存 |
| Quant | 確率過程、金融商品、価格評価 | 粒子エンジンへの依存 |
| Electronic | 電子密度、基底、電子状態の計算 | MDの拡張としての埋め込み |
| 実行・表示 | 設定の入出力、開始・停止、保存、描画 | JavaScriptによる別の計算実装 |

MD導入時のcrate名は `ergion-core`、`ergion-md`、後続の `ergion-quant`、`ergion-electronic` を想定する。Dynamicsは製品上の名前、`ergion-md`は初期のMD実装名。現在は `crates/ergion-core` に積分器、`crates/ergion-lab` に等速直線運動・調和振動子・共通設定・Native CLI・Wasm境界、`studio/` に画面を配置する。LabはMD実装ではない。未実装の分野に空のcrateを先回りして作らない。

## 数値問題の境界

計算の基準はCPU上の`f64`とする。一般ODE、位置・運動量を分ける力学系、将来の伊藤型SDEは、それぞれ必要な演算を明示する。すべてを一つの`solve(f)`や巨大なtraitへ押し込まない。

- 一般ODE: RK4。調和振動子など既知解で確認する。
- 分離可能な力学系: 固定刻みvelocity-Verlet。v0.1のMD本体に使う。
- SDE: 第2段で追加し、乱数・経路実行・統計を物理と金融で共有する。

`OdeProblem`、`SeparableHamiltonian`、`ItoSdeProblem`は境界を説明する仮の名前で、公開APIの確定ではない。共通化する実行制御と、手法ごとに異なる数学的構造を分ける。

## v0.1のMDモデル

必須範囲は3D、周期境界、NVE、単一種のforce-shifted Lennard–Jonesとする。初期仕様案は立方体セル、LJ換算単位（質量・sigma・epsilonを基準）とし、実装前に入力契約として確定する。

初期実装は全粒子対を一度ずつ評価するO(N²)の参照実装とする。最小イメージ法のカットオフはセル辺長の半分未満に制限する。重なる粒子、非有限値、非正の質量や時間刻みは入力検証で扱い、無言で補正しない。

標準LJポテンシャルを `phi(r)`、カットオフを `rc` とすると、採用する相互作用は次の形である。

```text
phi(r) = 4 epsilon [(sigma/r)^12 - (sigma/r)^6]
U(r)   = phi(r) - phi(rc) - (r - rc) phi'(rc)  (r < rc)
U(r)   = 0                                    (r >= rc)
F_i    = -grad_i U
```

カットオフでエネルギーと力がともに連続にゼロになる。[LAMMPSの定義](https://docs.lammps.org/pair_lj_smooth_linear.html)を比較基準にする。通常のLJ、energy-shiftのみのLJと混同しない。長距離補正を自動追加しない。

温度は運動エネルギーと自由度から算出する。重心運動除去の有無、拘束による自由度の扱い、単位を出力に明示し、初期化条件と整合させる。NVEの計算中に温度を合わせ直す処理は入れない。

## 設定・状態・再現性

設定とチェックポイントを区別する。設定は計算条件、チェックポイントは再開に必要な状態を表す。両者をNativeとWasmで共有し、読み書きは実行層が担当する。等速直線運動および調和振動子の設定はスキーマ版1のJSONとし、[Studioの入力仕様](studio.md)で定義する。MD設定とチェックポイントの形式は未決定。

| データ | 保存すべき情報 |
| --- | --- |
| 設定 | スキーマ版、単位系、初期条件、粒子・セル・力場、時間刻み、実行量、観測間隔、乱数を使う場合の方式とseed |
| チェックポイント | スキーマ版、対応設定、位置・速度または運動量、時刻・ステップ数、積分器の再開に必要な状態、必要な乱数内部状態 |
| 結果メタデータ | 設定、コード版、実行ターゲット、観測値の定義、検証に必要な条件 |

再構築可能な力などは再計算してもよいが、連続実行との一致を検証する。seedだけでは進行中の乱数状態を復元できると仮定しない。未対応のスキーマ版や不整合な状態は明示的に拒否する。

同一条件の再実行を目指すが、異なる実行環境間のビット単位一致は保証しない。数値比較は絶対・相対許容誤差を定義して行う。初期比較では同一の明示的な粒子状態を使い、乱数初期化の差と積分誤差を分離する。

## ブラウザと計算の境界

計算はWeb Worker内のRust/Wasmで実行する。複数ステップをまとめて進め、間引いた観測値と粒子状態をUIへ渡す。計算バッチ間でWorkerがメッセージを処理できるようにし、停止要求を受け付ける。粒子ごと・ステップごとのJavaScript往復は避ける。

一時停止後の再開は同じ状態を継続する。条件変更後の実行は新規実行として扱い、既存軌道の途中で無言に条件を書き換えない。描画頻度と数値積分の時間刻みを独立させる。

ブラウザのファイル取得・ダウンロード、Nativeのファイル操作、OSスレッド管理はCoreの外に置く。[Rustの対象ターゲット資料](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html)に記載された標準ライブラリの制約を実装時にも確認する。

## 依存ライブラリの方針

依存ライブラリは極力入れない。一度きりの確認だけなら使ってよい。カリキュラムは基礎力学、電磁気学、解析力学、微分方程式の順に進み、基礎力学の内部も単純なものから進める（画面にいまあるページは、最初の部分である古典力学で、等速直線運動と等加速度直線運動です。これより後の部分は、まだページにしていません）。スカラーの等速直線運動・調和振動子には`nalgebra`、`faer`、`wgpu`を導入していない。後続の単位でベクトル・小行列、大規模行列分解、GPU基盤が必要になっても、先に公式仕様、Native/Wasm対応、ライセンス、必要機能を技術検証し、範囲を広げるためだけには足さない。計算の図は Studio のWebページとし、GitHub Pages（https://coil398.github.io/Ergion/）やCursorローカルで閲覧する。別の描画スタックは足さない。式の解説は計算を行う関数の rustdoc（`crates/ergion-lab/src/uniform.rs` の `UniformSimulation`）に置き、画面は動く粒子を示してその関数を参照する。初回StudioはVite＋TypeScript＋Canvas、Wasm境界はwasm-bindgen、共通設定はSerdeで構成する。

WebGPU計算は第3段で検討する。CPUの`f64`参照実装を残し、GPUの精度・並列集計による差を用途別の許容誤差で評価する。v0.1の描画技術とGPU計算基盤の採用を混同しない。

## MD実装に向けて確定する事項

- 設定・チェックポイントの形式、スキーマ、互換性方針。
- 初期粒子配置・速度分布、単位、自由度と温度の定義。
- MDのcrate配置と公開API、導入する数値ライブラリのバージョン。
- 3D描画手段、正式な対応ブラウザ、配信方法。
- 各テストの入力、許容誤差、実行時間予算。
