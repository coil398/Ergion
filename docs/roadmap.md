# 開発ロードマップ

各段階は実行して結果を確認できる状態で区切る。以下はすべて未実装の計画であり、チェックの完了は実装と検証結果の両方で判断する。

## 第1段: v0.1 — ブラウザで動く最小MD

### 1. NativeとWasmの最小経路

- [ ] 入力・単位・保存形式とworkspace配置を確定する。
- [ ] RustコアをNativeとWasmの両方でビルド・実行する。
- [ ] 共通設定から調和振動子を計算し、ブラウザにも結果を表示する。
- [ ] RK4とvelocity-Verletの解析解・収束検証を追加する。

Wasm対応をMD完成後へ先送りせず、数値コアの初期段階から確かめる。

### 2. LJ粒子系を端から端まで接続

- [ ] 全粒子対参照実装、周期境界、force-shifted LJを実装する。
- [ ] 固定刻みvelocity-VerletでNVEを実行する。
- [ ] 同一設定・初期状態をCLIとWorker内のWasmで実行する。
- [ ] 3D粒子表示と、温度・全エネルギーの推移を表示する。
- [ ] 力・エネルギー勾配、境界、時間刻み依存を検証する。

### 3. 再実行可能な環境として仕上げる

- [ ] 条件変更、新規実行、一時停止・再開を実装する。
- [ ] 設定の共有、チェックポイントの保存・読み込みを実装する。
- [ ] 途中再開と連続実行、NativeとWasmの比較を行う。
- [ ] 不正入力と計算失敗をCLI・画面から確認できるようにする。
- [ ] 実際に動く導入手順、再現用設定、検証結果を公開する。

v0.1の完成判定は[検証計画](validation.md)に従う。金融・電子状態・GPU計算・近接リスト・CPU並列化はこの段階に追加しない。

## 第2段: 金融で共通コアを実証

最小MDの直後に着手する。MDの大規模化より先に、分野をまたぐ再利用性を検証する。

- 伊藤型SDE、経路ごとの乱数、平均・分散などの統計を導入する。
- 物理側のブラウン運動と、金融側の小さな価格過程を同じ数値基盤に載せる。
- 金融の初期例は幾何ブラウン運動と欧州型オプション評価を候補とし、着手時に確定する。
- 既知の分布・モーメント・価格を用い、離散化誤差とMonte Carlo誤差を分けて検証する。

完了条件: 物理と金融が共通のSDE・乱数・統計を利用し、QuantがMDの粒子や力場に依存していないこと。経路IDとseedによる再現性を定義する。

## 第3段: 実用的な規模へ

近接粒子リスト、CPU並列化、WebGPU計算を個別に導入する。全粒子対・CPU倍精度の参照実装を残す。

完了条件: 参照実装との誤差を説明でき、粒子数・経路数・実行時間・計算環境をそろえた測定で性能向上を示せること。最適化ごとに数値結果への影響を検証する。

## 第4段: 電子状態へ

空間離散化、固有値計算、Poisson計算、自己無撞着計算を、小さく検証可能な電子系から積み上げる。Electronicは独立した分野モジュールとする。

「現代的な電子状態計算環境」は長期的な製品像であり、WIEN2k互換やAPW+lo実装をv0.1で約束するものではない。手法、基底、境界条件、参照解はこの段階の設計で選ぶ。
