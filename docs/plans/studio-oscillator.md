# Studio 初回実装とv0.1残作業計画

基準: febc0b0。初回実装の対象は一粒子の等速直線運動（$x = x_0 + v t$）および調和振動子をNative CLIとブラウザで実行する最初の完成単位。

更新: 2026-09-30。最初の単元を一粒子の等速直線運動（$x = x_0 + v t$）とし、Studio 画面・学習用文章・CLI・Wasm を実装済み（調和振動子コードもライブラリ・CLIとして維持）。以下の完了記録を保持し、後半にv0.1までの未完了作業を記す。今回の作業は計画更新と初回実装のpushまでで、MD実装はまだ開始していない。

## 範囲と所有

- Rust担当: Cargo workspace、ergion-core、ergion-lab、共通JSON設定例。
- 親: Studio、Worker通信、設定共有、ブラウザテスト、文書と統合。
- Coreは分野固有モデル・入出力を持たない。Labは等速直線運動・検証用の調和振動子と実行境界を所有。
- LJ、3D MD、温度、金融、チェックポイント保存は後続。今回の設定保存は状態保存と区別する。

初回実装の開始時点では5文書のみで実装・再利用ヘルパーはなかった。crateはCoreとLabの2つ、Studioは独立ディレクトリ。未実装分野の空crateは作らない。

## 技術選定

公式registryと資料を確認し、Vite 8.3.0、TypeScript 7.0.2、wasm-bindgen 0.2.128、serde 1.0.229、serde_json 1.0.151、Playwright 1.63.0を選定。描画はCanvas、UIは標準DOM。環境にあるwasm-pack 0.13.1をまず利用し、実ビルドで互換性を確認する。依存ライブラリは極力入れない。一度きりの確認だけなら使ってよい。スカラーの調和振動子には nalgebra を足さない。

## 画面方針

計算と学習の画面である。結果を中心にした確認の場で、式の解説・理論・引数仕様・テスト検証は計算する関数の rustdoc（`crates/ergion-lab/src/uniform.rs` の `UniformSimulation`）に置き、画面は動く粒子を示してその関数を参照する。GitHub Pages（https://coil398.github.io/Ergion/）やCursorローカルで閲覧する。図は別の描画スタックにしない。白い作図面、温かい紙色のページ、青の数値解、青緑の解析解、煉瓦色の誤差を使う。配色は紙面 #ffffff、背景 #f4efe6、文字 #1c1915、数値解 #003153、解析解 #167b87、誤差 #a86240。書体は日本語の可読性を優先したシステムゴシック、数式はserif、数値は等幅で桁をそろえる。

```text
Ergion Studio                    計算状態
実験ナビ | 等速直線運動 / 数式
         | 条件フォーム | 等速直線運動の計算（rustdoc参照）
         |              | 粒子の直線運動・現在値
         |              | 軌道を読む（位置・速度の時系列）
         |              | 実行操作・計算進捗
```

比較した構成は「概要カードを並べるダッシュボード」と「計算条件に隣接した一枚の作図面」。本件は実験が主目的なので後者を選ぶ。装飾的な統計カードや未実装ナビゲーションは置かない。狭い画面では条件・作図面を縦に並べる。

## 形式検証を含む実行順

[Lean・TLA+による形式検証計画](formal-verification.md)は計画のみである。非同期計算の確認にはTLA+を用いることをユーザー確認済み。現在の単位は調和振動子であり、この順には着手しない。形式検証と分子動力学を並行させず、より難しいモデルへは飛ばない。後続の単位を始めるときは、その理論の文書を計算と同じ変更に含め、図は別の描画スタックにしない。

1. 後続に回す。調和振動子と Worker を固定したうえで、Lean の実数モデルと TLC の有限モデルを検証する（F0〜F2）。分子動力学の契約設計とは並行しない。
2. その後に、分子動力学の契約、参照実装、実行接続、画面、チェックポイントがある。Lennard–Jones と保存再開を足す単位では、証明と非同期モデルの拡張（F3）を同じ変更に含める。
3. 数値・ブラウザ検証と、証明・モデル検査の証拠を CI にまとめるのは、それらの単位のあとである（F4）。未実施の形式検証を、先に完成条件へ繰り上げない。

実数の証明をRustのf64全域の証明と呼ばず、有限モデルの検査を無制限の非同期実行の証明と呼ばない。

## v0.1までの残作業

後続の目標は、3D・周期境界・NVE・force-shifted Lennard–Jonesの小規模MDを、同じ設定でCLIとブラウザから実行し、状態を保存・再開できること。カリキュラムは基礎力学、電磁気学、解析力学、微分方程式の順に進み、基礎力学の内部も単純なものから進める。画面にいまあるページは、最初の部分である古典力学で、等速直線運動と等加速度直線運動です。これより後の部分は、まだページにしていません。この一覧の後続には着手しません。[ロードマップ](../roadmap.md)と[検証計画](../validation.md)を受入の基準とする。

等速直線運動（および調和振動子）で完成した操作・設定共有は再利用する。以下の未チェックはMDへの対応を示し、既存機能の完了を取り消さない。金融、電子状態、近接リスト、CPU並列化、WebGPU計算はv0.1に含めない。

## 所有範囲・リスク・復旧

実装時の担当は段階ごとに割り当てる。MDモデルと数値検証、実行境界、Studio、文書・統合の所有を分け、Config／Snapshot／Worker通信・Cargo.lock・package-lock.jsonは契約確定後に直列更新する。共有ファイルを複数担当が同時に変更しない。

- 調和振動子の既存契約とテストを保つ。既存保存設定を無言で別モデルとして解釈しない。
- LJの符号・二重計数・カットオフの取り違えは、既知値と数値勾配で検出する。
- 初期粒子の重なりや不安定な条件を黙って補正しない。入力検証と計算失敗を区別する。
- 長時間軌道の完全一致や環境間のビット一致を受入条件にしない。物理量と明示した誤差で比較する。
- 生成物は定義元から再生成する。全粒子対・CPU倍精度の参照を削除しない。
- 検証済みの変更は main にコミットする。ブランチは切らない。プルリクエストは作らない。失敗時は未完成の機能を完成扱いせず直前の検証済み版を基準に原因を修正する。他担当の変更の破棄、既存データの上書きは復旧手段にしない。
