# Ergion のページの確認

ページを完成と呼ぶ前に、確認する人はこの手順をすべて行います。書く側の規則は `.cursor/skills/ergion-implement/SKILL.md` です。

## 1. 変えたページを開く

差分を読むだけの確認は、確認ではありません。変えたページを、幅 1440px と 390px、明るい配色と暗い配色で開きます。

## 2. 語を一つずつ書き出す

- 見出しの隅の語（corner chip、`quiet-label`）、式の下の注記（`equation-note`）、ボタンの文字を、ページごとにすべて書き出します。
- 次の語が画面にあれば不合格です: つながり、確認済、隅の語としての厳密解、換算単位、隅の語としての有理数、公開の前、式を満たす関数、配色、明るい、暗い、端末、暗くする、明るくする、誤差は実線、計算時間、CLI。
- 読者が意味を尋ねる語は不合格です。終端時刻は \(t = \Delta t \times\) ステップ数なので、`t = 10.00` のようにその量で書くこと。時間刻みとステップ数はフィールドの名前として残します。
- ボタン、見出し、または次の段落を言い直すだけの文は不合格です。「変更した条件は、適用後の新しい計算に使います。」も、CLI の文も不合格です。ページに、読者のための CLI はありません。
- 隅の語と注記は、見出しにない具体的な事実（例: \(f(x) = x^2 - 2\)）だけが合格です。見出しを言い換える語、分類を名付ける語は不合格です。見出しの右のカードは、ページが始まる式一つだけです。
- 配色の切り替えは、明るいページで月、暗いページで太陽のアイコン一つで、画面に語がないこと。
- +t の文字は +t、終端から同じ数を除くボタンの文字は -t で、+t の隣にあること。再生、一時停止、ループ再生、1ステップは短い語のままであること。操作の名前が文（計算時間を伸ばす、計算時間を延ばす）なら不合格です。
- サンプルが式をライブラリ呼び出しの中に隠す、または CLI に触れるなら不合格です。実行は、その繰り返しの点をコードの下のグラフに描くこと。
- ヘッダーに標語がないこと。文に Rust のパスや型名がないこと。f64、丸め、証明のファイル名についての段落がないこと。

## 3. 中身を確かめる

- 読み順が、式、図、手順、例、関連ページ、証明であること。図は長い導出の前にあること。証明は最後で、命題と原文だけであること。
- 手順の代数が飛んでいないこと。行列式から因数分解した多項式へ一足で移るような飛びは不合格です。
- 記号がすべて名付けられていること。画面の数ごとに、厳密か近似かが書いてあること。
- 例が紙と鉛筆で確かめられること。その数がライブラリの返した値として画面に出ること。
- 図が、軸と主張のあるグラフで、明るい配色と暗い配色の両方があること。言葉のないアイコンは不合格です。
- ページが式を計算し直していないこと。数はライブラリが返したものであること。
- 関連ページがリンクだけで、二つめの説明文も隅の語もないこと。
- 日本語が `.cursor/skills/ergion-japanese/SKILL.md` に従っていること。

## 4. 記録する

不合格の項目ごとに、ページと行を書きます（例: `studio/src/eigen.ts:42 行列式から因数分解へ飛んでいる`）。すべての項目が合格になるまで、そのページを完成と呼びません。
